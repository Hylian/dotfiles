# Rebuild Zellij Fork on `baumkuchen` and Land the Scroll Tuning

**Date:** 2026-08-19
**Host:** `baumkuchen` (macOS 27.0 / 26A5416b, M5 Pro, arm64) — client role
**Scope:** local fork build (`Hylian/zellij` @ `hylian/latency`), `chezmoi apply` of pending scroll config, [SYSTEM.md](SYSTEM.md).

---

## 1. Why

`chezmoi status` showed drift the source had carried since 2026-08-11 but this host had never applied:

| Target | Source | Live |
| --- | --- | --- |
| `.config/ghostty/config` | `mouse-scroll-multiplier = precision:0.33333,discrete:1` | `precision:0.75,discrete:1` |
| `.config/zellij/config.kdl` | `scroll_acceleration_factor 10.0`, `scroll_inertia false` | `3.5`, key absent |

Applying blind would have been wrong. `~/.local/bin/zellij` here was the **2026-08-07** build
(`strings … scroll_inertia` → 0 hits), i.e. the *inertia-coupled* engine. That build silently
ignores the unknown `scroll_inertia` key — `zellij --config … setup --check` still reports
`[CONFIG FILE]: Well defined.` — so the factor `10.0` would have fed the old coupled path and
produced ~10x post-swipe coasting, paired with a ghostty multiplier calibrated for the
*decoupled* engine. Rebuild first, then apply.

## 2. Build

Checkout `~/dev/zellij` was already in sync (`git rev-list --left-right --count origin/hylian/latency...HEAD` → `0 0`) at `d296b7e7`, and the 2026-08-11 inertia work was present in the tree — only the installed binary was stale. Prereqs all in place (`protoc` via brew, `mandown` in `~/.cargo/bin`, toolchain 1.92.0, sccache).

```
cargo xtask install ~/.local/bin/zellij
# plugins (wasm): 41.54s
# workspace release: 2m42
# total: 209s
```

Modified `zellij-utils/assets/plugins/*.wasm` in the worktree afterwards is expected — regenerated by the build.

## 3. The SIGKILL Trap (new detail)

The install "succeeded" and the binary was immediately unrunnable:

```
$ ~/.local/bin/zellij --version
rc=137        # SIGKILL
```

Evidence gathered before touching anything:

- `cmp ~/.local/bin/zellij ~/dev/zellij/target/release/zellij` → **identical**
- both report the same ad-hoc, linker-signed `CDHash=8c91f815a3323e29a29eeaf2db68195f1eead827`
- `codesign --verify --verbose` → *valid on disk*, *satisfies its Designated Requirement*
- `~/dev/zellij/target/release/zellij --version` → `zellij 0.44.3`, rc=0
- `pgrep -fl zellij` → two live **servers** (`verdant-jellyfish`, `stellar-stegosaurus`) still executing the old image *from that same path*

So it is not a signing defect. `cargo xtask install` overwrites the file **in place**, and while an
old image from that vnode is still executing, the kernel's cached signature/page hashes no longer
match the new contents → AMFI kills every fresh exec. Identical bytes, identical CDHash, clean
`codesign -v`: **signature verification does not detect this.**

Fix is to give the file a new inode:

```sh
rm ~/.local/bin/zellij && cp ~/dev/zellij/target/release/zellij ~/.local/bin/zellij
```

Running servers hold the unlinked old inode open, so live sessions are unaffected.
`codesign -s - --force` also clears it, for the same reason — it rewrites the file.

## 4. Apply & Verify

```
chezmoi apply      # clean; run_onchange_after_30-update-desktop-database.sh.tmpl is
                   # `if eq .chezmoi.os "linux"` guarded, renders empty on macOS
chezmoi status     # empty
```

- `~/.config/ghostty/config:46` → `mouse-scroll-multiplier = precision:0.33333,discrete:1`
- `~/.config/zellij/config.kdl:479,484` → `scroll_acceleration_factor 10.0`, `scroll_inertia false`
- `zellij setup --check` → `[CONFIG FILE]: Well defined.`
- Proof the new engine actually *parses* the key rather than ignoring it: a copy with
  `scroll_inertia notabool` now fails with `Failed to parse Zellij configuration` / *Failed to
  deserialize KDL node* pointing at line 484, rc=1. The 2026-08-07 binary accepted that same file.

## 5. Resolved: Old Servers Retired, Cache Swept

Both 2026-08-07 servers (`verdant-jellyfish`, `stellar-stegosaurus`) are gone; the only live server is
`joyous-donkey` (started 14:40, post-rebuild), so the decoupled acceleration is live in the session in use.

Housekeeping in the same pass — seven stale detached test sessions from 27 days earlier
(`ts_Launch`, `ts_Messag`, `ts_0`–`ts_3`, `ts_test`, all `EXITED - attach to resurrect`) reaped with
`zellij delete-session`. That clears resurrection data only, so two residues were removed by hand:

- `contract_version_1/session_info/`: 6 orphaned `session-metadata.kdl` dirs
  (`adventurous-piano`, `awesome-horse`, `excellent-megalodon`, `glowing-cuckoo`, `smoke-real`,
  `test_parse_check`) — dead servers, invisible to `list-sessions`. Kept `joyous-donkey`.
- cache root: 137 of 143 empty per-session UUID data dirs (`-mtime +0` only, so everything created
  today, including the live server's, was left alone). `permissions.kdl` and `contract_version_1/`
  untouched per the standing rule.

Smoke test after the sweep: a fresh `zellij -s reap_smoke` came up and appeared in `list-sessions`,
then exited cleanly with its client — plugin permissions survived, nothing to re-grant.
