## 1. Host & Machine Matrix

* **Workstation (Linux):** `shined` — Primary Linux development machine.
* **Secondary Linux:** `eterna` — Linux machine.
* **Clients (macOS):** `shined-mac`, `baumkuchen`, and `midnight-future` — Apple silicon laptops running macOS (Ghostty + aerospace/sketchybar/borders). Each carries per-host `aerospace.toml.tmpl` blocks and runs the locally built zellij + zjstatus forks.
* **Primary Remote Workflow:** macOS Client running **Ghostty** -> SSH into Linux Workstation (`shined`) -> **Zellij** multiplexer session.

### Privacy & Security Policy
* **Public Repository:** Absolute zero-secrets policy. No API tokens, credentials, or private work paths.
* **Work Separation & Host-Local Alias Overlay:** Work-specific aliases, internal hostnames, and private paths live strictly in external untracked files (e.g. `~/.config/zsh/galiases`, `paths`, `aliases`, `gemini`) sourced conditionally by [dot_zshrc.tmpl](../dot_zshrc.tmpl). Public templates (such as [dot_config/aerospace/aerospace.toml.tmpl](../dot_config/aerospace/aerospace.toml.tmpl)) reference only opaque semantic alias names (`rwd`, `rwc`) rather than internal flags or script paths.

### Repository Upstream Synchronization & SSH Key Caching
* **Autonomous Git Push/Pull:** `chez` automatically pulls upstream (`GIT_SSH_COMMAND="ssh -o BatchMode=yes" git pull --ff-only`) upon session activation to sync changes made across machines, and pushes (`GIT_SSH_COMMAND="ssh -o BatchMode=yes" git push origin main`) following each conventional commit.
* **Linux (`shined` / `eterna`) SSH Agent Topology:**
  - `systemd --user` runs `ssh-agent.service` listening at `/run/user/$(id -u)/openssh_agent` (`$SSH_AUTH_SOCK`).
  - User session lingering (`loginctl enable-linger`) is enabled, keeping `ssh-agent.service` alive across disconnects, Zellij sessions, and terminal closes.
  - `~/.ssh/config` configures `Host github.com` with `IdentityFile ~/.ssh/id_ed25519`, `IdentitiesOnly yes`, and `AddKeysToAgent yes`.
  - Passphrase authentication is required only once per boot: running any interactive git/ssh command or `ssh-add ~/.ssh/id_ed25519` inserts the decrypted key into the user-wide `ssh-agent`, where it remains cached in memory for the agent/skill to use autonomously.
* **macOS Clients (`shined-mac` / `baumkuchen` / `midnight-future`):**
  - Configured with `IdentityFile ~/.ssh/id_ed25519`, `IdentitiesOnly yes`, and `AddKeysToAgent yes` in `~/.ssh/config` (plus `UseKeychain yes` on non-gnubby hosts; `gnubby-ssh` on `shined-mac` rejects `UseKeychain`, so unlock via `ssh-add ~/.ssh/id_ed25519` into the running agent).
  - Remote SSH connections from macOS clients into `shined` forward the unlocked agent via `ForwardAgent yes`, synchronized into Zellij panes via `$XDG_RUNTIME_DIR/zellij-env/client`.
* **Non-Interactive Batch Mode:** All automated git remote operations enforce `GIT_SSH_COMMAND="ssh -o BatchMode=yes"` so unauthenticated states fail immediately with an informative prompt to Rachel rather than hanging or blocking on stdin.

### B. Terminal Emulator (Ghostty)
* **Configuration:** Shared chezmoi template (`dot_config/ghostty/config.tmpl`).
* **Key Features:** PragmataPro Mono font, custom dark/light theme palette, `clipboard-read = allow`, `shell-integration-features = true`.
* **Clipboard Interception:** Ghostty intercepts ANSI OSC 52 escape sequences emitted over SSH to update the macOS system pasteboard.
* **Scroll Behavior:** Configured with `mouse-scroll-multiplier = 0.75` on Linux (and `precision:0.75,discrete:1` on macOS) to scale GTK/Wayland pixel-level trackpad scroll events for responsive, natural finger travel sensitivity without affecting system-wide GUI applications like Chrome. Pairs with Zellij's 1-line scroll event handling (`lines: 1` in `mouse_handler.rs` and `screen.rs`) so every trackpad scroll event advances exactly one line at a time for smooth, fluid viewport animation.
* **File URI Link Handler (`zellij-edit`):** Registered as the default `x-scheme-handler/file` (and `text/plain`) desktop handler via `~/.local/share/applications/zellij-edit.desktop` and `~/.config/mimeapps.list`. When a `file://` link (e.g. `file:///path/to/file#L123-L145`) is clicked in Ghostty with `link-url = true`, Ghostty dispatches to GIO/XDG which invokes `zellij-edit`. The script decodes percent-encoded URL paths, extracts line numbers (`#L123`, `:123`), queries the active or `(current)` Zellij session, and runs `zellij --session <session> action edit [-l <line>] [--cwd <dir>] <path>` to open the target file in Neovim in a new pane in the current Zellij tab (falling back to spawning Ghostty + Neovim if Zellij is not running).

### C. Terminal Multiplexer (Zellij 0.45.x)
* **Build Provenance (macOS clients & Linux workstation):** Zellij is built from the personal fork `Hylian/zellij`, branch `hylian/latency` (rebased onto upstream `v0.45.1`), and installed to `~/.local/bin/zellij`, which precedes `/opt/homebrew/bin` on PATH (that is the only copy on `baumkuchen` — no `~/.cargo/bin/zellij`). On `shined` and `baumkuchen` the brew package was removed; on `midnight-future` it is still installed and simply shadowed by PATH order — equivalent in effect and it avoids the autoremove hazard below. Rebuild with `cargo xtask install ~/.local/bin/zellij`, which needs `protobuf` (brew) and `mandown` (`cargo install --locked mandown`); ~3 min for a full rebuild on an M4 Max (16 cores), 3m30 on an M5 Pro (15 cores) with a cold sccache. Cargo is configured via [dot_cargo/config.toml.tmpl](../dot_cargo/config.toml.tmpl): `incremental = false`, `jobs` rendered from the host's own CPU count, and `rustc-wrapper = "sccache"` emitted **only** when `lookPath "sccache"` succeeds — an unconditional wrapper fails every cargo invocation on a host without sccache, and a hardcoded `jobs = 64` oversubscribes a 16-core client. **On macOS, install to a fresh inode:** `cargo xtask install` overwrites the binary in place, and while an old server image from that path is still executing the kernel's cached signature for the vnode no longer matches the new pages, so the next exec dies with SIGKILL (exit 137). Reproduced on `baumkuchen` 2026-08-19: bytes `cmp`-identical to `target/release/zellij`, same ad-hoc linker-signed CDHash, and `codesign --verify` reporting *valid on disk / satisfies its Designated Requirement* — **`codesign -v` does not detect this**. Fix by giving the file a new inode (`rm ~/.local/bin/zellij && cp target/release/zellij ~/.local/bin/zellij`); `codesign -s - --force` also works because it rewrites the file. Running servers keep the unlinked old inode, so live sessions are untouched. Note that `cargo xtask install` copies unconditionally and preserves the source mtime, and the re-sign then rewrites the binary, so neither mtime nor a `shasum` against `target/release/zellij` proves anything about what is installed: hash the pair *before* signing, and otherwise confirm content with `codesign -v` and `zellij --version`. Beware `brew uninstall` here: it autoremoves orphaned formulae, and removing zellij also swept `python@3.14`, `python@3.13`, `certifi`, `pydantic`, `cffi` and `pycparser` (all reinstalled since). Other hosts may still run stock zellij; every config below is written to work either way. The branch is fully pushed to `origin` and carries the latency commits (`/proc` cwd reads, `close_range` syscall, parameter-less CSI K/J erase sequences, dynamic new-tab CWD naming, initial `CwdChanged` preservation), the dynamic smooth scroll queue with configurable gesture acceleration (`scroll_acceleration_factor 10.0` in [dot_config/zellij/config.kdl.tmpl](../dot_config/zellij/config.kdl.tmpl), protobuf tag `70`) and 67% (`(n * 2 + 1) / 3`) catch-up scaling across both incoming wheel events (`mouse_handler.rs`, where `int_lines` is merged into `pending_lines` before immediate draining so high-frequency 120Hz trackpad events immediately flush any prior backlog) and the 14ms background drain loop (`tab/mod.rs`), decoupled live swipe acceleration vs post-gesture inertia (`scroll_inertia false` in `config.kdl`, protobuf tag `71`), and OSC 133 CLI actions (`scroll-to-previous-prompt`, `scroll-to-next-prompt`, `select-command-at-scroll-position`, `copy-last-command-output`), automatic `Scroll` mode sync on prompt jumps, and multi-line prompt support (`next_prompt_line_delta` & `add_osc133_marker` deduplication). See [2026-09-24-increase-zellij-scroll-catchup-factor.md](2026-09-24-increase-zellij-scroll-catchup-factor.md) and [2026-09-24-zellij-045-rebase-and-osc133.md](2026-09-24-zellij-045-rebase-and-osc133.md). **`origin/hylian/latency` has been force-pushed** — an older local clone diverges and must be `git reset --hard origin/hylian/latency` before building. Backups: `hylian/latency-0.44.3` (pre-0.45.1 rebase), `hylian/latency-pre-zjstatus` (with the render patches), `hylian/latency-pre-cleanup` (pre-review state).
* **zjstatus Build & Autorender (macOS clients):** zjstatus is built from the personal fork `Hylian/zjstatus`, branch `hylian/autorender`, and installed to `~/.config/zellij/plugins/zjstatus.wasm`. Build with `cargo build --release` (pins toolchain 1.95.0 + `wasm32-wasip1`, ~50s cold, ~15s incremental) and copy `target/wasm32-wasip1/release/zjstatus.wasm` into place; `cargo test` needs the `wasmtime` runner from brew. `cargo build --release --features tracing` yields a plugin that logs every event, widget result and printed bar to `/host/.zjstatus.log` (i.e. `~/.zjstatus.log` for a session started in `$HOME`) — the fastest way to tell "the widget produced nothing" from "the bar dropped it". Three patches, all pushed to `origin`: (1) `should_render` in the `Event::RunCommandResult` arm when the stored result differs in `exit_code`, `stdout` or `stderr` (`context` excluded — it carries a per-invocation timestamp), since upstream stores the value and never asks for a repaint, leaving a new branch waiting on the render timer; pane-switch repaint 700ms → **47ms**, zero extra processes. (2) Rejection of out-of-order stale command results. (3) A local `PaneId -> PathBuf` mirror fed from asynchronous `CwdChanged` events, used as fallback when `get_pane_cwd()` blows zellij's 100ms `GetPaneCwd` budget — without it a `None` cwd wedged that pane's widget forever, since the OS cwd never changed and no `CwdChanged` was coming. See [2026-07-25-move-autorender-fix-into-zjstatus.md](2026-07-25-move-autorender-fix-into-zjstatus.md).
* **Rust Toolchain (macOS clients):** `brew install rustup` is keg-only and no longer ships `rustup-init`; its shims live in `/opt/homebrew/opt/rustup/bin`, which [dot_zshrc.tmpl](../dot_zshrc.tmpl) adds to PATH behind a `-d` guard along with `~/.cargo/bin` (where `cargo install` puts `mandown`). Both fork checkouts pin their toolchain through `rust-toolchain.toml` — zjstatus 1.95.0, zellij 1.95.0 — so `rustup toolchain install` both, each with the `wasm32-wasip1` target. Both forks are tracked directly inside this dotfiles repository as git submodules under `software/zellij` (branch `hylian/latency`) and `software/zjstatus` (branch `hylian/autorender`), ignored from chezmoi deployment via [.chezmoiignore](../.chezmoiignore).
* **Submodule Tracking & Per-Machine Build Receipts (`manage-forks.sh`):** Pinned submodule commits in `Hylian/dotfiles` define the canonical fleet version for both forks (`zellij` and `zjstatus`). Each machine independently tracks its installed build state via JSON receipts in `~/.local/state/builds/<fork>.json` (containing commit SHA, target path, build timestamp, hostname, OS, and arch). Orchestrated autonomously by the `chez` skill via `.agents/skills/chez/scripts/manage-forks.sh`:
  - `manage-forks.sh status`: Compares submodule commits against local machine receipts and binary targets.
  - `manage-forks.sh check`: Fast non-zero exit if any installed binary is missing or behind submodule HEAD.
  - `manage-forks.sh sync`: Recursively updates submodules (with automatic `SSH_AUTH_SOCK` discovery from `zellij-env/` and BatchMode SSH + HTTPS fallback for non-interactive subshells) and triggers builds for any outdated fork, recording fresh receipts.
  - `manage-forks.sh build <fork>`: Rebuilds and installs a fork, installing via a temporary target to replace the binary on a fresh inode (preventing Linux `ETXTBSY` against running sessions and macOS vnode CDHash mismatch `SIGKILL`), ad-hoc codesigning on macOS (`codesign -s - --force`), and pruning zjstatus plugin cache.
  - `manage-forks.sh record <fork> [commit]`: Seeds or updates machine receipts for existing builds.
* **Cache & Plugin Reload (macOS):** the cache dir is `~/Library/Caches/org.Zellij-Contributors.Zellij` (`zellij setup --check` prints it). A new `zjstatus.wasm` on disk is **not** enough after a rebuild — the tree also holds per-plugin state (`<url-path-safe>/plugin_cache`), hash-named blobs downloaded for URL-sourced plugins, per-session UUID data dirs, and per-version dirs. Clear it, but keep two things: `permissions.kdl` (the `RunCommands` grants; [run_onchange_after_20-zjstatus-plugin-permissions.sh.tmpl](../run_onchange_after_20-zjstatus-plugin-permissions.sh.tmpl) will not re-seed unless its rendered contents change) and `contract_version_1/` (holds `session_info`, which is how `list-sessions`/`attach` find a **live** server — deleting it while a long-lived session is running risks orphaning it). Compiled modules are not cached on disk in 0.45.x — `Module::new` runs on every load — so the stale-plugin risk is entirely the plugin_cache and download blobs. Running servers keep the old binary and old plugin in memory: a rebuild only reaches a session started afterwards.
* **Session Reaping Leaves Residue:** `zellij delete-session <name>` removes the resurrection data, so the session stops appearing in `list-sessions`, but it does **not** clean two other places: `contract_version_1/session_info/<name>/session-metadata.kdl` and the session's UUID data dir at the cache root (an empty `file:`/`https:` path scaffold per plugin the session loaded). `list-sessions` ignores both — 143 UUID scaffolds and 6 orphaned `session-metadata.kdl` files had accumulated on `baumkuchen` before the 2026-08-19 sweep — so they are cosmetic clutter, not resurrectable sessions. Reap only entries older than the live session's start (`find … -mtime +0`) and never the UUID dir of a running server.
* **Status Bar Width (`format_hide_on_overlength`):** the layout sets it `"true"` with `format_precedence "lrc"`, so when left (mode + tabs) and right exceed the pane width zjstatus drops the **entire right section** rather than truncating it or dropping tabs. The git branch is the widest variable part, so a bar that fits while empty stops fitting the moment a branch appears: the branch never shows, the section blinks out, and the plugin looks broken while its own tracing shows the widget returning the right value. To prevent right-section drop on narrow terminal widths (e.g. 120 columns), `git-status.sh` truncates branch names longer than 24 characters to 23 chars + `…` (display length 24). See [2026-09-08-move-zjstatus-tabs-to-left.md](2026-09-08-move-zjstatus-tabs-to-left.md).
* **Plugin Selection & Permissions:** [dot_config/zellij/layouts/default.kdl.tmpl](../dot_config/zellij/layouts/default.kdl.tmpl) uses chezmoi's `stat` to pick the local build when present and fall back to the zjstatus release URL otherwise, and declares `ZJSTATUS_AUTORENDER` through zjstatus's own `command_git_branch_env` — no server patch is involved in advertising the capability. **Zellij keys its plugin permission cache by plugin location**, so switching URL → local path needs a fresh `RunCommands` grant, and the prompt is drawn inside the one-row status bar pane where it cannot be seen or answered; the bar just renders empty. [run_onchange_after_20-zjstatus-plugin-permissions.sh.tmpl](../run_onchange_after_20-zjstatus-plugin-permissions.sh.tmpl) seeds the cache entry and no-ops without a local build. chezmoi decides whether to re-run a `run_onchange_` script by hashing its **rendered contents**, so the script embeds `{{ if stat $wasm }}` presence in a comment; without that, a host that builds the plugin after its first apply never re-runs it and comes up with an empty bar.
* **Status Bar Git Widget:** `command_git_branch` runs `dot_config/zellij/widgets/executable_git-status.sh` (rendered to `~/.config/zellij/widgets/git-status.sh`) rather than an inline KDL command, with `command_git_branch_interval "5"` and `--no-optional-locks` on every git call. zjstatus invalidates focused-cwd widgets only when the cwd genuinely changes, but then re-spawns the command on every render until a result lands — measured at ~18 invocations per pane switch — so the script memoises in two zero-fork tiers: a one-slot output memo (`$XDG_RUNTIME_DIR/zjstatus-git-memo.$ZELLIJ_SESSION_NAME`, TTL 1s) keyed by cwd and verified via `/proc/uptime` (or epoch fallback) with zero subprocess forks, and a per-repository dirty memo (`$GIT_DIR/zjstatus-dirty`, TTL 3s) guarding the O(worktree) `diff-index` scan. The branch is read from `$GIT_DIR/HEAD` with builtins (falling back to `$git symbolic-ref --short HEAD` / `$git rev-parse --short HEAD` only when encountering Git's `reftable` backend `.invalid` sentinel in `$GIT_DIR/HEAD`) and truncated to 24 display characters (`…`) via pure POSIX parameter expansion when exceeding 24 characters to avoid width blowout. **The output memo must stay per session** — a shared slot makes concurrent sessions invalidate each other every render, which with the repaint kick below becomes a feedback loop (measured 4 invocations/s while idle). Burst memo hit latency is ~1.9ms (down from ~38ms); sustained switching in a 40k-file repo costs ~33% of a core, down from ~197%. See [2026-07-24-bound-zjstatus-git-widget-cost.md](2026-07-24-bound-zjstatus-git-widget-cost.md), [2026-08-05-zero-fork-git-status-memo.md](2026-08-05-zero-fork-git-status-memo.md), [2026-09-08-support-git-reftable-backend-in-zjstatus-widget.md](2026-09-08-support-git-reftable-backend-in-zjstatus-widget.md), and [2026-09-08-truncate-git-branch-in-zjstatus.md](2026-09-08-truncate-git-branch-in-zjstatus.md).
* **Initial Session & New-Tab CWD Resolution (`09c11194` & `f38e8e99`):** `Pty::capture_initial_cwd` in `zellij` records the fork-time CWD in `initial_terminal_cwds` (used as fallback by `GetPaneCwd` and `spawn_terminals_for_layout`) rather than `terminal_cwds`, ensuring that the shell's first `_zellij_osc7_cwd` (`notify_cwd_from_osc7`) or `update_and_report_cwds` poll always emits the initial `Event::CwdChanged` to plugins. In `zjstatus`, `update_focused_pane()` is invoked on `Event::TabUpdate`, `Event::CwdChanged` (when `focused_pane_id` is unset), `Event::Timer`, and `pipe()` (when `focused_pane_cwd` is `None`), and retries `get_pane_cwd` until `focused_pane_cwd.is_some()`. Additionally, `/tmp/zjstatus-cmd-cache.<name>` stores a `cwd:<path>` header alongside `stdout` and is cached once in memory per `CommandWidget`, preventing cross-repository stale branch flashes when switching to a different directory while keeping frame-0 seeding instant.
* **Status Bar Repaint Kick (release-zjstatus fallback):** A zjstatus that stores a command result without scheduling a render leaves a new branch waiting for the 1s render timer — median 700ms after a pane switch. When `ZJSTATUS_AUTORENDER` is **absent** the widget pipes `zjstatus::pipe::zjs_render_kick::-` (a pipe name no format references, so it only forces a render) whenever its value or directory changed, giving a median of 67ms; with the patched plugin the marker is set by the layout and the kick is skipped entirely. `zellij pipe` is a *streaming* client: it needs `</dev/null` and a plain-sh watchdog (macOS has no `timeout(1)`) or it blocks forever against a dead or wedged server, holding a socket each time — this exhausted file descriptors and crashed a server once. The watchdog subshell must also redirect **stdout**, since zellij reads the command's output to EOF and a grandchild holding that pipe stalls the result for the full watchdog window. See [2026-07-24-repaint-git-widget-on-change.md](2026-07-24-repaint-git-widget-on-change.md).
* **Event-Driven Refresh:** Zsh `precmd` runs `_zellij_osc7_cwd` (emits `\e]7;file://...` via pure parameter expansion, no subprocess, so Zellij learns the pane CWD synchronously and can invalidate immediately on pane switch) and `_zellij_refresh_git_branch` (deletes both widget memos with `zf_rm`, then pipes `zjstatus::rerun::git_branch`). `chpwd` runs `zellij_tab_name_update` (asynchronously renaming the tab to the CWD basename) and `_zellij_track_git_dirty_cache`, which resolves the repo memo path once per directory so the per-prompt hook stays fork-free. `_zellij_track_git_dirty_cache` is initialized lazily on first prompt (`_zellij_refresh_git_branch`) or `chpwd` to eliminate synchronous git subprocesses during `.zshrc` boot. `_zellij_refresh_git_branch` is defined **only** in `dot_zshrc.tmpl` and carries its own `$ZELLIJ` guard; the fzf widgets call it directly.
* **Scrollback Editor & Pane Frame Style:** `scrollback_editor "nvim"`, `pane_frames true`, and `pane_frame_style "full"` (preserving full 4-sided rounded-corner pane frames after Zellij 0.45.x changed the default `PaneFrameStyle` to `"titles"`).
* **Automatic Mode Locking (`zellij-autolock`):** Loaded via `~/.config/zellij/plugins/zellij-autolock.wasm` with `triggers "nvim"` to automatically switch Zellij into Locked mode when Neovim is focused so all Alt bindings pass through to the editor. Configured with `reaction_seconds "0.2"` in [dot_config/zellij/config.kdl.tmpl](../dot_config/zellij/config.kdl.tmpl) to debounce trailing `PaneUpdate` events during tab transitions and prevent double mode-flicker.
* **Keyboard Protocol & SSH Repeat Stability:** `support_kitty_keyboard_protocol` is explicitly set to `false`. This prevents multiplexer-level Kitty protocol negotiation and ensures Ctrl modifier keys emit atomic single-byte C0 control characters (e.g. `^K` -> `\x0b`). Over SSH, rapid key repeats (such as scrolling in `fzf` pickers) avoid TCP packet fragmentation and escape sequence delay timeouts, completely eliminating dropped escapes and partial escape string leaks.
* **Tab Creation & CWD Inheritance:** The default layout ([dot_config/zellij/layouts/default.kdl.tmpl](../dot_config/zellij/layouts/default.kdl.tmpl)) defines the default tab template without a global `cwd` override. When opening a new tab via `Alt + n` (or tab mode `n`), Zellij's server dynamically discovers the focused pane's runtime working directory via `/proc/<pid>/cwd` and spawns the new tab's shell in that exact directory (matching `Alt + s` pane creation and Neovim's `<A-n>` behavior). In `Hylian/zellij` (`hylian/latency`), `ScreenInstruction::NewTab` automatically derives unnamed tab titles directly from the focused pane's working directory basename (`~` for `$HOME`, `/` for root) on frame 0, eliminating default `Tab #N` titles and intermediate flashes without any shell hooks or IPC overhead. See [2026-09-08-rename-tab-to-cwd-on-new-tab-creation.md](2026-09-08-rename-tab-to-cwd-on-new-tab-creation.md).

### D. Shell (Zsh) & Prompt (Starship)
* **Shell Framework & Startup Optimization (~16ms `.zshrc`, ~80ms total wall time):** `zsh` + `antigen` with compiled wordcode bundles (`~/.antigen/bundles/*/*.zwc`), auto-compiled user configs (`~/.zshrc.zwc`, `~/.zshenv.zwc`, `~/.config/zsh/widgets.zwc`, `~/.config/zsh/aliases.zwc`), and cached completion in `$XDG_CACHE_HOME/zsh/zcompdump(.zwc)`. When bundles are installed on disk, [dot_zshrc.tmpl](../dot_zshrc.tmpl) bypasses Antigen's 2,000-line dynamic runtime parser (`~39ms` saved) and loads the essential Oh-My-Zsh libraries (`completion`, `directories`, `functions`, `git`, `history`, `key-bindings`, `misc`, `termsupport`) and 4 active plugin scripts directly (automatically falling back to `antigen apply` if any bundle directory is missing on a fresh host). Sets `ANTIGEN_COMPINIT_OPTS="-C"`, `ZSH_DISABLE_COMPFIX="true"`, and `DISABLE_LS_COLORS="true"`, running `compinit -C -d "$ZSH_CACHE_DIR/zcompdump"` exactly once before Oh-My-Zsh libs (`compaudit` reduced from 4 scans / 41ms to 0ms). In [dot_zshenv.tmpl](../dot_zshenv.tmpl), sets `export google_zsh_flysolo=1` and `[[ -n "$ZELLIJ" ]] && setopt NO_GLOBAL_RCS` to skip redundant `/etc/zsh/zshrc` `compinit` and `/usr/bin/skippy --check-bypass` forks inside Zellij panes. ## 3. Standard Keybinding Conventions

### Zellij & Neovim Tab Management (Omnipresent Across Modes `{'n', 'i', 'v', 't'}`)
* `Alt` is the primary modifier for pane, tab, and navigation management in both Zellij and Neovim. Because `zellij-autolock` locks Zellij when Neovim is focused, all Alt chords are handled inside Neovim across normal (`n`), insert (`i`), visual (`v`), and terminal (`t`) modes (including floating popups like `fzf-lua`).
* `Alt + \`` / `Alt + ~` (`<A-`>` / `<A-~>` / `<A-S-`>`): `ToggleTab` — quick switch back and forth between the two most recent Zellij tabs (dynamically tracked in Neovim via `current-tab-info`).

* `Alt + 1` .. `Alt + 0`: Switch directly to Zellij tab 1 .. 10.
* `Alt + Ctrl + Left` / `Alt + Ctrl + Right`: Move Zellij tab left/right.
* `Alt + s`: New Zellij pane (right) in current working directory.
* `Alt + n`: New Zellij tab in current working directory.
* `Alt + f`: Toggle fullscreen Zellij pane.
* `<A-h/j/k/l>`: Seamless directional focus navigation across Neovim splits and Zellij panes (`smart-splits.nvim`, works in floats and terminal buffers).
* `<A-C-h/j/k/l>`: Directional split resizing across Neovim windows and Zellij panes (`smart-splits.nvim`).
* `<A-S-h/j/k/l>`: Move Zellij pane directionally.
* `<A-S-[>` / `<A-S-]>` / `<A-{>` / `<A-}>`: Swap Zellij layout previous/next.
* `<A-[>` / `<A-]>`: Break Zellij pane left/right.
* `<A-+>` / `<A-=>` / `<A-->`: Increase/decrease Zellij pane size.
* `<A-z>`: Switch Zellij back to normal unlocked mode.
* `Alt + y`: `CopyLastCommandOutput` — copies the output of the last finished OSC 133 shell command in the active Zellij terminal pane to the clipboard (bound in Zellij `shared_except "locked"` and `Scroll`/`Search` modes).
* `Alt + Up` / `Alt + Down` (and `Ctrl + k` / `Ctrl + j` / `[` / `]` in `Scroll`/`Search` mode): `ScrollToPreviousPrompt` / `ScrollToNextPrompt` — jumps between OSC 133 shell prompts in the focused Zellij terminal pane (and automatically syncs Zellij `Scroll` / `Normal` mode).

* `Alt + d` / `Alt + q`: Smart close — in floating popups (like `fzf-lua`), dismisses the float; in editor/splits, closes window; in terminal pane, closes pane.
* `Alt + Shift + q` (`<A-S-q>` / `<A-Q>`): Force quit (`:q!<CR>`).
* `Alt + w` (`<A-w>`): Save buffer (`:w<CR>`).
* `<A-S-Left>` / `<A-S-Right>`: Previous / next Neovim tab (`tabp` / `tabn`).
* `<A-S-1>` .. `<A-S-0>` / `<A-!>` .. `<A-)>`: Switch directly to Neovim tab 1 .. 10 (`1gt` .. `10gt`).
* `<C-A-S-Left>` / `<C-A-S-Right>`: Move Neovim tab left / right (`-tabmove` / `+tabmove`).
* `<A-S-n>`: Open new Neovim tab (`:$tabnew<CR>`).
* `<A-S-d>`: Close Neovim tab (`tabclose`).

* Deferred via `zvm_after_init_commands` to ensure persistence across `zsh-vi-mode` (`zvm_init`) keymap resets.
* `^k`: `zoxide-fzf-curdir` (interactive directory jump scoped to current directory subtree; calls `_zellij_refresh_git_branch`, which drops the widget memos and pipes `zjstatus::rerun::git_branch`, for instant branch status refresh).
* `^o`: `zoxide-fzf` (interactive global zoxide query and jump; same instant refresh path as `^k`).
* **`^j` is reserved for `accept-line` and MUST NOT be bound to a widget.** `^J` is LF, and the tty line discipline runs in cooked mode with `ICRNL` between `accept-line` and the next ZLE read — an Enter autorepeated into that window is enqueued as LF and dispatched as `^J`, making Enter and Ctrl-J the same byte with no way to distinguish them. A held Enter therefore fires whatever `^j` is bound to; widening the window (hook forks on `chpwd`) widens the race. `widgets.tmpl` rebinds `^j` to `accept-line` explicitly in all three keymaps so re-sourcing it in a live shell cannot leave a stale binding. See [2026-07-26-held-enter-triggers-zoxide-widget.md](2026-07-26-held-enter-triggers-zoxide-widget.md). No other control key in this set has a CR relationship.
* `^g`: `cd-fzf` (interactive directory navigator).
* `^f`: `rg-fzf` (interactive ripgrep file/line search into Neovim).
* `^v`: `vim-fzf` (interactive fd file search into Neovim).
* `^n`: `git-pick-fzf` (interactive git commit picker with delta preview, pastes/appends selected commit SHA(s) to current line).
* `^b`: `git-branch-fzf` (interactive git branch picker sorted with current branch on top, local branches by most recent, then remote branches, with pretty short log preview).
